Installed figures use static projections. To enable 3D rotation and layout selection, render with options(grip.vignette.interactive = TRUE) and ivue and rgl installed.

Explore a structural mesh, a branching power network, a recursive carpet, and a porous volume. Every figure compares metric-MDS with metric-MDS + edge-KK using the same graph and lengths. The remaining nine examples, including dwt_307, Les Miserables, curved surfaces, and the intrinsic tree, are in the extended gallery.

The layouts use SGD, grip’s default metric-MDS backend. They use uniform stress weights; they do not reproduce the inverse-squared weighting in the Zheng et al. paper. See Metric MDS for that comparison.

Reading the gallery

Blue is metric MDS; orange is MDS followed by edge-KK. Gray, when present, shows the coordinates used to construct the graph. Each visible layout includes all its edges. Switching layouts preserves the camera and scale. Each layout is Procrustes-aligned to the generating coordinates (or to metric MDS when no generating coordinates are available). Corresponding vertices are matched by their graph indices; translation and rotation/reflection minimize their summed squared separations. No resizing is used to make the layouts agree. Generating coordinates show where a geometric graph came from, but need not realize its graph shortest-path distances as straight-line separations.

Each graph also supports an interactive 3D view made with ivue. Use the visible layout selector to choose metric-MDS, metric-MDS + edge-KK, or both. Gray generating coordinates remain visible where available. Drag to rotate and scroll to zoom. By default, a static view shows the same metric-MDS coordinates and alignment as the initial interactive view.

Each table reports two errors. Graph-distance error measures the fit to all shortest-path distances; edge-length error measures the fit to supplied edge lengths. Both are root-mean-square errors divided by the root-mean-square target length, so zero is exact agreement and lower is better. Scores use the returned coordinates without fitting an extra scale. Each stage’s elapsed time is also listed; preparation is excluded, and the refinement time is additional to the MDS time. These are single-workstation timings, not a speed comparison.

Start with SGD metric MDS

This small example creates a weighted tree and draws it in 3D with SGD. The saved gallery also compares an optional edge-KK stage; it is not a recommended automatic second step.

g <- kary.tree.weighted.graph(k = 2, depth = 5, depth.decay = .85,
                            branch.spread = .2, normalize = 'none')
prepared <- prepare.graph.geodesic.mds(
  edges = g$edges, n = g$n, edge.weights = g$edge_weights)
mds <- suppressWarnings(metric.mds(
  prepared = prepared, dim = 3, backend = 'sgd', init = 'random',
  n.init = 3, max.iter = 80, seed = 2026, diagnostics = FALSE))

Use mds$coords as the default result. For larger graphs, pass raw graph inputs to metric.mds(approximation="sparse", backend="sgd", ...) rather than creating this dense preparation; see sparse MDS.

Optional edge-length comparison

The following reproduces the gallery’s additional comparison. Retain it only when its independent diagnostics support the intended use.

refined <- edge.kk(
  coords = mds$coords, prepared = prepared, dim = 3,
  stiffness.method = 'uniform', density.mix.schedule = 1,
  scale.mode = 'identity', max.iter = 100,
  return.trace = FALSE, diagnostics = FALSE)

MDS tries to fit shortest-path distances between all pairs of vertices. Edge-KK adjusts the drawing to fit directly connected vertices. Here every edge has equal influence during refinement, and scale.mode = "identity" keeps its target length fixed. An improvement in edge lengths can come with a worse fit to distances between more widely separated vertices.

We use three random starts for MDS, retaining the one with the lowest stress, and allow 80 passes per start. Reaching that limit can produce an iteration_limit warning; the small example suppresses it, while the saved gallery records it. Refinement allows 100 iterations. These are illustration settings, not settings chosen to make either stage win. All fits use seed 2026.

Each dataset supplies n, edges, edge_weights, vertex_data, and provenance. For these six examples, vertex indices follow the original matrix rows. The six graphs are connected; no vertices were dropped or connecting edges added. We use unit edge lengths and preserve the original matrix values separately. For example, Les Miserables coappearance counts describe connection strength, so they are not passed to the layout functions as distances.

More graph constructors

Need Public entry points Output
Topology alone edges.path(), edges.mesh(), edges.kary.tree(), the other primitive edges.*() generators Two-column edge matrix; no bundled reference coordinates or lengths.
A finite perforated grid keep.periodic.holes(), keep.asymmetric.notches(), keep.slit.channels(), keep.staggered.windows(), then occupied.mesh.surface.graph() A keep matrix followed by a complete weighted graph bundle.
A recursive pattern Square mask.*() helpers, cubic mask.cube.*() arrays, or triangle/tetrahedron masks, then the matching recursive.*.surface.graph() A mask followed by a recursively generated weighted bundle.
A regular reference surface mesh.surface.graph(), cylinder.surface.graph(), sphere.surface.graph(), torus.surface.graph() Edges, lengths, 3D reference coordinates, and parameters.
Irregular surfaces or volumes The irregular.*.surface.graph() and irregular.*.solid.graph() families Deterministic geometric constructions; “irregular” does not imply random sampling.
Triangular-lattice or polyhedral topology The three triangulated.*.surface.graph() families Graph edges and reference coordinates; the public bundles do not expose triangular faces.
Randomly sampled rectangle sampled.rectangle.surface.graph() or plural sampled.rectangle.surface.graphs() One graph or a sequence on a shared sampled point set.
Intrinsic lengths without an embedding kary.tree.weighted.graph() Tree edges, lengths, depths, parents, and edge metadata.

The construction recipes in the extended gallery illustrate additional families. Use complete public bundles; standalone embeddings and specialized edge builders used inside them are internal functions. A name ending in surface.graph is not a promise of a triangle mesh: occupied-cube families, for example, connect occupied cells and can include interior vertices.

Constructing other graph families

Use a constructor when you need controlled topology or generating coordinates. The extended gallery includes executable recipes and 3D views of a folded irregular annulus and a recursive Vicsek pattern. Change one feature at a time when studying its effect. The complete constructor catalog is in Finding your way around grip.

Repeat the gallery

The small tree example runs when this vignette is built. The gallery uses saved layouts so rebuilding the document does not repeat the larger fits. To draw any graph yourself, use its construction line above followed by the two-step example. Keep dim = 3 and the same edge lengths in both steps.

The full recipe is installed as scripts/graph-examples.R. Instructions for rebuilding the saved layouts and images are in the reproduction guide. The saved file retains the settings, software version, all MDS starts, warnings, and any unsuccessful fits. This gallery uses dense shortest-path distances; check graph size before increasing the construction sizes substantially.
